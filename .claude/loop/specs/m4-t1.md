## 関数シグネチャ
```ts
import { useRef } from 'react';
import { SWIPE_THRESHOLD_PX } from '../lib/constants';

interface SwipeNavOptions {
  onSwipeLeft?: () => void;
  onSwipeRight?: () => void;
  disabled?: boolean;
}
interface SwipeHandlers {
  onTouchStart: (e: React.TouchEvent) => void;
  onTouchEnd: (e: React.TouchEvent) => void;
}
export function useSwipeNavigation(opts: SwipeNavOptions): SwipeHandlers
```

## 実装概要（EditorPage L291-331 判定ロジックをコピー流用）
- `touchStartXRef`/`touchStartYRef`（number|null）。`onTouchStart`: `e.touches[0]` の clientX/Y を ref に保存。
- `onTouchEnd`: start が null → return。`opts.disabled` が true → return。`e.changedTouches[0]` から dx,dy。
  - `Math.abs(dx) < SWIPE_THRESHOLD_PX` → return（閾値未満棄却）
  - `Math.abs(dx) <= Math.abs(dy) * 2` → return（縦優位棄却＝水平優位2:1）
  - `dx < 0` → `opts.onSwipeLeft?.()`（左スワイプ）
  - `dx > 0` → `opts.onSwipeRight?.()`（右スワイプ）
  - 終了時 start ref を null クリア
- preventDefault しない（click/長押し非干渉＝plan M-2）。
- IME ガード: 一覧に入力欄なしのため composition 監視は配線不要。本フックは isComposing を扱わない（EditorPage の textarea 固有事情でありフック責務外。流用は判定構造のみ）。
