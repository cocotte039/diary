# M1-T2: DBSchema memos + upgrade追加分岐 + dateKey export（TDD）

## 変更対象
- `src/lib/db.ts`
- `src/lib/db.test.ts`（移行テスト先行 RED）

## 実装概要
1. `DiaryDB extends DBSchema` に `memos` ストア追加:
   ```ts
   memos: {
     key: string;
     value: Memo;
     indexes: { 'by-createdAt': string; 'by-syncStatus': SyncStatus };
   }
   ```
2. `getDB()` の `upgrade` 末尾に **既存3ストアのコードを1文字も変更せず** 追加分岐:
   ```ts
   if (!db.objectStoreNames.contains('memos')) {
     const ms = db.createObjectStore('memos', { keyPath: 'id' });
     ms.createIndex('by-createdAt', 'createdAt');
     ms.createIndex('by-syncStatus', 'syncStatus');
   }
   ```
   `oldVersion<3` 条件は不要（既存の contains ガード方式に統一、v1/v2/新規を一律カバー）。
3. `function dateKey` を `export function dateKey` に変更（挙動完全不変）。

## 受入条件（TDD: テスト先行）
- 🔵 [RED→GREEN] 旧 v2 スキーマを `indexedDB.open(DB_NAME, 2)`（volumes/pages/meta を手動 createObjectStore + データ投入）→ close → `_resetDBForTests` → `getDB()`（v3）昇格後、投入した volume/page/meta が全件無傷で読める
- 🔵 新規（DBなし）→ `getDB()` で4ストア（volumes/pages/meta/memos）生成、memos 空
- 🔵 `dateKey` が export され、既存 `findPageByDate`/`getDateSetInMonth` のテストが緑のまま（挙動不変）
- 🔵 `npm run test:run` 緑

## テスト方針
- `db.test.ts` に `describe('v2→v3 migration')`: fake-indexeddb で v2 を明示構築→データ投入→ハンドルリセット→ v3 open→既存データ検証。
- TDD: 移行テストを **先に書いて RED**（memos 追加前は v3 open 自体は通るが、memos ストア未定義で後続 CRUD テストが赤）。実際は移行テスト自体は v2→v3 で緑になりやすいので、`db.objectStoreNames` に 'memos' 含むアサーションを先に書いて RED にする。

## Key Links
M1-T3 の CRUD が memos ストアを使用。dateKey は M3-T4/LogListPage・M4-T2/github が消費。

## 注意
- **既存日記の不可侵**: volumes/pages/meta の upgrade コードは絶対に触れない。追加分岐は末尾に足すのみ。
- idb の version downgrade 不可。DB_VERSION は今後戻さない前提（ロールバック方針）。
- `_resetDBForTests` / `wipeDB`（`indexedDB.deleteDatabase(DB_NAME)`）の既存テストヘルパを移行テストで活用。
