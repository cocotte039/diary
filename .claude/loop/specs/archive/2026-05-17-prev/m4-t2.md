# M4-T2: buildMemoFileContent + putMemoFile + syncPendingMemos（TDD）

## 変更対象
- `src/lib/github.ts`
- `src/lib/github.test.ts`

## 参照（コピー流用・汎用化しない）
`putPage`（SHA取得→422再取得リトライ）、`syncPendingPages`（settings/online ガード→pending ループ→backoff→{synced,failed}）、`b64encode`、`shaCache`。

## 新規シグネチャ
- `buildMemoFileContent(memosOfDay: Memo[]): string` — createdAt 昇順、各 `## HH:MM:SS\n{content}\n` 連結（時刻は dateKey と同じローカル時刻基準）。
- `putMemoFile(path: string, content: string): Promise<void>` — putPage の SHA/422 ロジックをコピー。
- `syncPendingMemos(): Promise<{synced:number; failed:number}>`:
  1. settings/online ガード（syncPendingPages 同型、無/オフラインで {0,0} 早期return）
  2. `getPendingMemos()` → `dateKey(createdAt)` でユニーク日集合 D
  3. 各 d∈D: `getAllMemos()` から d の全メモ抽出→createdAt 昇順→`buildMemoFileContent`→**生成に使った memo id 配列を保持**→`putMemoFile('memos/'+d+'.md', content)`→成功で `markMemosSyncedByDay(d, ids)`
  4. backoff リトライ syncPendingPages 同型
- `syncPendingMemosBackground()` — fire-and-forget ヘルパ（syncPendingPagesBackground 同型）。
- `BACKUP_PATH_RE` は volumes 専用のまま変更しない（memos/*.md は parse 対象外＝既存挙動）。

## 受入条件（TDD）
- 🔵 buildMemoFileContent: 同日複数メモを時刻昇順で `## HH:MM:SS\n本文` 連結
- 🔵 syncPendingMemos: モック octokit で `memos/YYYY-MM-DD.md` に PUT、成功で当該日メモ synced
- 🔵 生成→PUT 間に追加された pending メモは synced 化されない（生成時 id 集合のみ markSynced, E3/C2）
- 🔵 settings 無 or オフライン→ {0,0} 早期return（syncPendingPages 同型）
- 🔵 既存 syncPendingPages テスト回帰なし、shaCache 衝突なし（volumes/.. vs memos/.. パス分離）
- 🔵 `npm run test:run` 緑

## テスト方針
github.test.ts: octokit モック（既存パターン）。複数日 pending→各日 PUT 検証。生成後に新規 pending 追加→次回再生成対象を検証。早期 return。

`putPage` を汎用リファクタしない（コピーで回帰面積最小）。b64encode は UTF-8 安全な既存実装流用。
