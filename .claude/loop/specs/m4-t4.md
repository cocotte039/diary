# M4-T4: A12 削除日反映 空PUT（TDD）

## 変更対象
- `src/lib/github.ts`（syncPendingMemos に deleted-days 処理追加）
- `src/lib/github.test.ts`

## 実装概要（U1 採用: 空内容PUT）
`syncPendingMemos` の pending 日処理の後に:
- `getDeletedMemoDays()` の各 d について `putMemoFile('memos/'+d+'.md', '')`（空内容PUT）→成功で `removeDeletedMemoDay(d)`。
- deleteMemo（M1-T3 で実装済 A12）: 当日全削除時に addDeletedMemoDay 済み前提。

## 受入条件（TDD）
- 🔵 当日全メモ削除→ memos-deleted-days に当日 → syncPendingMemos が `memos/YYYY-MM-DD.md` に空内容 PUT
- 🔵 空PUT 成功で removeDeletedMemoDay（再実行で二重PUTしない）
- 🔵 当日にメモが残る削除（A12 の他メモ pending 化経路）→ deleted-days には入らず通常再生成で最新内容に更新（古い内容残存しない, E4）
- 🔵 deleted-day の PUT 失敗時は除去しない（次回再試行）
- 🔵 既存 syncPendingMemos（pending 日）テスト回帰なし
- 🔵 `npm run test:run` 緑

## テスト方針
github.test.ts: メモ投入→全削除→getDeletedMemoDays 確認→syncPendingMemos モック octokit→空内容 PUT & deleted-day 除去を検証。残存メモあり削除ケースの再生成も検証。

## Key Links
getDeletedMemoDays/removeDeletedMemoDay/deleteMemo(M1-T3)←。putMemoFile(M4-T2)←。syncPendingMemos が本番呼出。

## 注意
U1=空内容PUT（octokit deleteFile より実装小・putMemoFile 流用）。ファイル削除方式は採らない。
