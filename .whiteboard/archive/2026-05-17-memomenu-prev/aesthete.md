# Aesthete 分析（美しさ・UX・一貫性・静けさ整合）

確信度: 🔵 / 🟡 / 🔴

## 1. ヘッダー内 HeaderTabs + MemoMenu レイアウト整合
🔵 `.app-header` は `display:flex; justify-content:space-between; align-items:center`（global.css L75-77）。本棚は header 内に `<HeaderTabs/>` + `<BookshelfMenu/>` を並置 → タブ左・メニュー右に自然分割。
- LogListPage は現状 `<HeaderTabs/>` のみ（中央寄りでなく space-between で左寄せ + 余白）。MemoMenu を追加すると本棚と同じ「タブ左 / ハンバーガー右」になり、**2画面間のヘッダー構造が完全一致** → 画面遷移時の認知負荷ゼロ。🔵
- 注意: 🟡 本棚 .header は `align-items: baseline`（BookshelfPage.module.css L25）で上書き。LogListPage.module.css `.header` は空（L12-14）。MemoMenu のトリガーは 44px box。HeaderTabs はテキスト。baseline 揃えにすると本棚と視覚一致。LogListPage.module.css `.header` にも `align-items: baseline` 追加推奨（本棚と同一視覚）。

## 2. メモカレンダー vs 日記カレンダー 差別化
🔵 「別管理」はデータ次元の話。UI を変える必要はない。むしろ**同型 UI が正解**:
- ユーザーは「カレンダーから日付に飛ぶ」というメンタルモデルを本棚で既習。メモ側も同 UI なら学習不要。
- 文脈（メモ画面のメニューから開く）でスコープは自明。色/形を変えると「別物では？」と却って混乱・認知負荷増。
- 🔵 ドット色 `var(--color-text)` opacity 0.6 / サイズ 3px（Calendar.module.css L49-57）をそのまま流用。色追加なし = 静けさ厳守。
- 結論: 視覚は日記カレンダーと完全同一に。差別化は不要かつ有害。🔵

## 3. 瞬間スクロール vs スムース
🔵 要件「瞬間移動」+ 静けさ原則（過剰アニメ排除）→ `scrollIntoView({behavior:'auto', block:'start'})` が正解。
- スムーススクロールは「動き」を見せる演出 → 静けさ（注意を引かない）と相反。瞬間移動は「気づいたら目的地」で最も静か。🔵
- 🟡 ヘッダー被り懸念: `.body` は `overflow-y:auto`、ヘッダーは flex 上段の別要素（fixed でない, global.css 改修で position:fixed 廃止済）。`block:'start'` で section が .body スクロール領域の上端に来る。ヘッダーは .body の外（上）なので被らない。🔵 ただし section 上端ぴったりだと日付見出しが詰まって窮屈 → 視覚的余白として section に scroll-margin-top: 0.5rem 程度を許容範囲で検討（任意・静けさ範囲内）。🟡

## 4. 空メモ日タップ無反応の体験
🟡 日記カレンダーは空日タップで findPageByDate→最近接ページにフォールバック遷移（Calendar.tsx L51-54）。メモ版要件は「無反応」。
- 静けさ観点: 「タップしても何も起きない」は不親切に見えうるが、ドット有無で可否は視覚的に判別可能（ドット=押せる の暗黙ルールは日記で既習）。通知/トースト/シェイク等のフィードバックを足すのは静けさ違反。
- 結論: 無反応で正。ただしドットが「押せる場所」のアフォーダンスを十分担保していることが前提。ドット 3px は控えめだが日記で実績あり → 踏襲で可。🔵
- 🟡 任意改善: ドット無し日セルの opacity をわずかに下げる案もあるが、日記カレンダーと挙動を変える=一貫性崩れ。**やらない**推奨。

## 5. FAB の位置・アイコン・機能重複
🔵 本棚 FAB と同一（右下固定・鉛筆 SVG・/log/new）。メモ画面でも「書く」動作で自然。
- 🟡 機能重複懸念: HeaderTabs に「メモ」タブはあるが、これは画面切替であり「新規作成」ではない。FAB=作成、タブ=ナビゲーション で役割明確、重複なし。🔵
- メモ一覧から直接書ける導線は UX 向上（現状メモ作成は本棚 FAB 経由のみ → 一覧で「書きたい」と思った時の最短動線が無い欠落を補完）。🔵
- 位置: BookshelfPage.module.css `.fab` の bottom（片手リーチ最適化済 L138）流用。メモ画面も同位置で筋肉記憶一貫。🔵

## 6. メニュー項目順
🔵 本棚: 新しいノート / カレンダー / 設定。メモ: カレンダー / 設定（新規作成は FAB が担うため項目から除外）。
- 順序「カレンダー → 設定」は本棚の相対順（カレンダーが設定より上）を保持 → 一貫。🔵
- 「設定」が両画面で最下 = 共通の定位置。認知負荷最小。🔵

## 7. モーダル fade-in / overlay 整合
🔵 BookshelfPage.module.css の `fadeIn 200ms`（L98-103）・overlay `rgba(0,0,0,0.6)`（L92）。
- 200ms ≤ 200ms 制約内。rgba 黒は新規色でなく既存モーダル踏襲 → 静けさ整合。🔵
- 複製時もこの値を厳守。fade-in は「現れる」最小限の手がかりで過剰でない。🔵

## 8. 認知負荷 総評
🔵 本機能群は「本棚で既習のパターンをメモ画面に対称配置する」もの。新概念ゼロ・新色ゼロ・新アニメゼロ。静けさは損なわれない。
- むしろメモ画面の機能空白（メニュー無し・作成導線無し・日付ジャンプ無し）が本棚との非対称＝微妙な不整合だった。本機能で**2画面の操作体系が対称化**し、全体の一貫性は向上する。🔵

## 最重要 UX 指摘 3点
1. メモカレンダーは日記カレンダーと**完全同一の視覚**にすべき（差別化は混乱を生む・静けさ違反）。ドット色/サイズ流用必須。🔵
2. スクロールは `behavior:'auto'`（瞬間）厳守。スムースは静けさと相反。section の上端詰まり回避に scroll-margin-top 微量は任意で許容。🟡
3. LogListPage.module.css `.header` に `align-items: baseline` を追加し本棚ヘッダーと視覚完全一致させる（HeaderTabs + Menu の縦位置揃え）。🟡
