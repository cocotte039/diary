# Aesthete 分析（体験・美学・認知負荷・静けさ整合）

> Analyst Lead が実読のうえ体験視点で記述（Task 不可環境のため自己実施）。

## 1. FAB位置上昇 🔵
親指リーチ（natural thumb zone は画面下端から ~25-50% 上）。現状 `1.25rem`(~20px) は端すぎ。`3.5rem`(~56px) へ上昇は重心が画面隅から内側へ寄り、片手把持時の到達性向上。右端余白 `right` は不変で水平バランス維持。視覚的に隅から浮く印象が出るが FAB は元来フローティング要素で違和感小。静けさ適合（色/アニメ不変）。🔵 妥当。

## 2. 自動フォーカス 🔵 / 編集時は 🟡
- 新規(/log/new): FAB=「メモを書く」意図で開く → 即入力可能は摩擦最小化、静けさと整合（書く所作を妨げない）。🔵 強く推奨。
- 編集(/log/:id): 「読み返す」目的で開くケースあり。キーボード即展開は読書体験を阻害し得る。ただしユーザー明示要件・メモは短文前提・カーソル末尾配置（M4対策）なら再開編集の自然性が勝る。🟡 要件として受容、`preventScroll:true` でスクロール飛び抑制必須。

## 3. ゴシック化 🟡（喪失と利得の評価）
- 喪失: 明朝の「静謐・素の紙」情緒。当初コンセプト「メモ=素の紙(明朝)で日記(手書きKlee)と分離」の差別化が弱まる。
- 利得: 小サイズ画面での可読性・視認速度（観測ログ＝素早い記録/参照用途）。日記の手書き体(Klee One)とは依然フォントが異なり体験分離は保たれる（明朝でなくとも sans で差別化十分）。
- 一覧 `.preview` と編集 `.textarea` のフォント一致は一覧→編集の連続性で好ましい（同一テキストが同じ見え方）。🔵 一致は維持すべき（両方 `--font-family-ui`）。
- 結論: ユーザー協議で確定済。可読性優先は観測ログの実用目的に整合。docstring の「明朝＝素の紙」記述は「素の紙（ゴシック、可読性優先）」へ趣旨更新。🟡 受容。

## 4. タップ背景ハイライト — 具体推奨値 🔵
- `--color-rule`(rgba(255,255,255,0.08)) は背景 #1c1c20 上で知覚困難（薄すぎ・🟡）。
- 推奨: 既存 `--color-accent`(#3a3545) を使った淡背景。新規色禁止に適合。
- 具体値:
  ```css
  .row {
    border-radius: 6px;            /* 背景の角を柔らかく（任意・静けさ調） */
    transition: background-color 150ms ease;
  }
  .row:active { background-color: var(--color-accent); }
  ```
  `--color-accent` 全面はやや強い場合、`color-mix` 不使用方針なら accent そのままで可（press 中のみ・150ms で消える瞬間的フィードバックなので強すぎない）。🔵
- transition 150ms ≤200ms 制約適合。opacity 廃止で「行が薄くなる」より「行が沈む」触覚的フィードバックとなり tap 認知が明確。
- 注意: `border-radius` 追加は任意。最小変更優先なら background のみでも可（Lead 判断）。

## 5. 右スワイプ戻る + 左上「戻る」二重提供 🟡
- 認知負荷: 戻る手段が 2 つ（リンク + スワイプ）。発見可能性はリンクが担保、スワイプは「知っていれば速い」隠れ加速。iOS の edge-swipe-back メンタルモデルに合致 → 学習負荷低。🔵 二重提供は許容。
- 一貫性懸念: 他画面（EditorPage はページ送り、本棚は無し）とスワイプ意味が異なる。ただしメモ編集は 1 画面で「右スワイプ=戻る」は OS 標準作法と一致し直感的。🟡 メモ限定の作法として妥当。
- 左スワイプ無反応: メモ 1 画面につき次が無い。無反応は正しい（誤遷移ゼロ）。🔵

## 静けさ適合総括
全 5 変更とも 4 色制約・≤200ms・通知/バッジ無しを維持。新規色追加なし（タップ背景は既存 accent）。トランジション最大 150ms。原則違反なし。🔵
