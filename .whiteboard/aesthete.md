# Aesthete 分析（視覚・UX・一貫性・認知負荷）

## 体験統一の評価（R1/R2）

### 既存設計の意図と転換
- 🔵 現状は意図的「体験分離」: 日記=Klee One 手書き体+罫線ノート（連続文章・情緒）、メモ=ゴシック+素の紙（即時記録・可読性）。module.css L1-7／MemoEditorPage.tsx L28-30 が明示。
- 🟡 ユーザー要望は「メモを日記と同じに」＝統一志向。評価: アプリ全体のトーンが Klee One 手書き体で一貫し、本棚/日記/メモが同一の「ノート」世界観に収束。認知負荷は下がる（モード切替時のフォント切替がなくなる＝視覚的連続性向上）。デメリットは日記とメモの即時的見分けにくさだが、HeaderTabs/ヘッダー構造/罫線有無以外の文脈（URL・ヘッダーのメニュー差）で識別可。アプリの世界観統一の価値が体験分離の価値を上回ると判断（ユーザー要望とも合致）。

### 罫線がメモに与える印象
- 🟡 メモは短い断片中心。notebook 罫線(--color-rule=rgba(255,255,255,0.08) 極薄)は「書く場所の気配」程度で主張せず、空白でも煩くない（EditorPage で実証済の控えめさ）。手書き体+罫線で「走り書きノート」の情緒が出る＝メモの性質と親和的。短文で罫線が全面に出るのは EditorPage と同じ＝静けさ範囲内。
- 🔵 推奨: 罫線の起点は notebook.css の `background-position:0 0`＋上下padding 0 をそのまま採用し、.app-header 直下から1行目罫線が自然に始まる構造（EditorPage と同一）。独自 padding:1rem を残すと罫線位相がずれて美観破綻＝必ず notebook 標準に委譲。

### R2 一覧の情報階層
- 🔵 本文 .preview を Klee One 化＝一覧上でメモ本文が「手書きの言葉」として立ち上がる。
- 🔵 .dateHeading/.time/.empty を --font-family-ui（システムゴシック）維持＝メタ情報（日付・時刻・空状態）が本文と異なるフォントで視覚的に後退し、情報階層が明瞭化。手書き体=コンテンツ／ゴシック=システム の対比が一貫ルールとして全画面で機能（編集画面 createdAt も --font-family-ui）。これは情報構造上きわめて妥当＝R2' 強く支持。
- 🟡 .emptyMemo（空メモプレースホルダ「（空のメモ）」）は本文位置だが内容はシステム的注記。要件は --font-family-ui 削除＝Klee One 化指定。Klee One の opacity 0.3 で十分後退＝許容。一貫性より要件遵守を優先。

## R3 閉じる体験
- 🔵 「本棚」固定ラベル→「閉じる」: 設定は本来モーダル的・一時的画面。「閉じる」は「来た場所へ戻る」メンタルモデルと一致し、認知負荷減（"なぜ本棚に飛ぶ？"の違和感解消）。直前画面（本棚/メモ一覧）尊重は文脈保持の体験価値が高い。
- 🟡 ラベルは文字「閉じる」推奨（× アイコンは notebook 系ヘッダーにアイコン前例少、.app-header-link は文字主体・既存「本棚」「戻る」と統一感）。aria-label は「設定を閉じる」。.app-header-link スタイル（font-family-ui/0.75rem/opacity 0.3→0.6）を維持＝ヘッダーリンクの視覚一貫性保持。
- 🔵 既存「戻る」(MemoEditorPage)・「本棚」(EditorPage) と並ぶヘッダーリンク語彙に「閉じる」が加わる＝役割語彙が増えるが、各々文脈が異なり混乱しない（編集=戻る/設定=閉じる）。

## R4 スワイプ操作感・方向設計
- 🔵 HeaderTabs（明示タブ・発見性）＋スワイプ（高速・親指操作）の二層提供は妥当: 初見はタブで学習、習熟後はスワイプで高速化＝段階的開示。冗長でなく補完関係。下部タブバー新設しない方針とも整合（既存ヘッダー＋ジェスチャで足る）。
- 🟡 方向: HeaderTabs 並びは「本棚 / メモ」（左=本棚, 右=メモ）。要件＝本棚で左スワイプ→/log（メモ）、メモで右スワイプ→/（本棚）。これは「右にあるメモを見るため画面を左へ送る／左にある本棚を見るため右へ送る」＝コンテンツが空間配置通りに左右へスライドするメンタルモデルと一致し直感的（iOS の戻る=右スワイプとも非衝突＝アプリ内タブ移動として閉じている）。要件方向を支持。
- 🔵 視覚フィードバック: 静けさ原則（フィードバック最小・アニメ排除）＋瞬間遷移を採用。スワイプ追従アニメ/インジケータは静けさ違反かつ実装コスト大＝不要。遷移後の画面（ヘッダータブの opacity アクティブ強調）が即座に「今どちらか」を示す＝十分。アニメ無し瞬間遷移は本アプリのトーン（保存インジケータなし・暗黙的）と一貫。

## 静けさ原則チェック
- 🔵 新規色なし（フォント変更は色制約外）/ バッジ・カウンタ追加なし / transition 追加なし（スワイプは瞬間遷移＝transition 不要）/ R3 はラベル文言変更のみ。全要件 静けさ適合。
- 🔵 R1 で notebook.css の既存罫線(極薄1色)を流用＝新規視覚要素ゼロ。

## 推奨デザイン判断
1. R1: textarea へ `notebook-surface notebook-textarea` 付与、上下 padding は notebook 委譲（位相ずれ厳禁）。世界観統一を採る。
2. R2: 本文 Klee One 化、.dateHeading/.time/.empty は --font-family-ui 維持＝「手書き=本文／ゴシック=メタ」の一貫ルールを全画面で確立。.emptyMemo は要件通り Klee 化（opacity で後退）。
3. R3: 文字「閉じる」＋aria-label「設定を閉じる」、.app-header-link 維持、to={from} 直接遷移。
4. R4: タブ＋スワイプ二層、要件方向、瞬間遷移・フィードバック無し（静けさ）。
5. 設計意図コメント（体験分離）は「ユーザー要望により世界観統一」へ更新し将来の混乱を防ぐ。
